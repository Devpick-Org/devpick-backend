# Trace 서버 간 통신 구조

> Spring(백엔드) ↔ FastAPI(devpick-ai) 간 통신 스펙 정리.
> **현재 devpick-ai**(`main.py` + `app/api/internal/router.py`) 기준으로 동기화했다.

---

## 전체 구조

```
FastAPI (devpick-ai)                 Spring                       PostgreSQL / MongoDB
──────────────────                   ──────                       ────────────────────

[콘텐츠 수집 흐름]
SO / Velog / RSS 등 수집
    ↓ 정규화 (PushService)
POST /internal/contents ─────────→ contents 테이블에 저장
(FastAPI → Spring)                 (canonical_url 기준 중복 스킵)

[AI 기능 흐름 — 사용자 요청]
                    사용자 요청
                        ↓
              Spring 공개 API만 외부 노출
                        ↓
         POST /internal/* + X-Internal-Key  ←── Spring WebClient (내부망)
         (질문 개선, AI 답변, 유사 질문, 리포트 인사이트, 4레벨 요약 배치 등)
                        ↓
                   AI 응답 반환
                        ↓
              Spring이 Redis / MongoDB 캐싱 (요약·퀴즈 등)
```

**핵심 원칙: FastAPI는 PostgreSQL에 직접 접근하지 않는다.**
콘텐츠 저장은 반드시 Spring API(`POST /internal/contents`)를 통해서만 한다.

**devpick-ai 인증:** `app/api/deps.py`의 `verify_internal_key` — 요청 헤더 **`X-Internal-Key`** 가 FastAPI 환경변수 **`INTERNAL_API_KEY`** 와 일치해야 한다. Spring 쪽은 **`AI_SERVER_INTERNAL_KEY`** / `ai.server.internal-key` 로 동일 값을 설정한다.

## 1. FastAPI → Spring (콘텐츠 수집 전송)

### `POST /internal/contents`

FastAPI가 수집·정규화한 콘텐츠를 배치로 Spring에 전달. Spring이 PostgreSQL에 저장.

- **URL**: `http://spring서버:8080/internal/contents`
- **인증**: 없음 (Nginx에서 외부 차단 예정 — 내부망 전용)
- **Content-Type**: `application/json`

**Request Body** (배열):

```json
[
  {
    "source_name": "velog",
    "title": "React 18 동시성 렌더링 완전 정복",
    "author": "홍근",
    "canonical_url": "https://velog.io/@honggeun/react-18",
    "published_at": "2026-03-10T09:00:00Z",
    "preview": "React 18에서 추가된 동시성 렌더링을 설명합니다...",
    "body_candidate": "본문 전체 텍스트...",
    "is_original_visible": true,
    "thumbnail_url": "https://velog.velcdn.com/images/...",
    "license_type": "cc-by",
    "tags": ["React", "Frontend", "JavaScript"]
  }
]
```

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `source_name` | string | O | 수집 소스 (`velog`, `stackoverflow`, `github` 등) |
| `title` | string | O | 글 제목 |
| `author` | string | X | 작성자 |
| `canonical_url` | string | O | 원본 URL — **중복 제거 기준** |
| `published_at` | string | X | ISO 8601 형식 (`2026-03-10T09:00:00Z`) |
| `preview` | string | X | 미리보기 텍스트 |
| `body_candidate` | string | X | 본문 전체 |
| `is_original_visible` | boolean | O | 원문 링크 노출 여부 |
| `thumbnail_url` | string | X | 썸네일 이미지 URL |
| `license_type` | string | X | 라이선스 (`cc-by`, `cc-by-sa`, `unknown` 등) |
| `tags` | string[] | X | 태그 목록 |

**Response**:

```json
{
  "success": true,
  "data": {
    "saved": 8,
    "skipped": 2,
    "total": 10
  }
}
```

> `skipped`는 `canonical_url`이 이미 존재하는 중복 건수.

## 2. Spring → FastAPI (devpick-ai 실제 라우트)

- **Base URL**: `http://ai-server:8000` (Docker) / `http://localhost:8000` (로컬)
- **Spring 설정**: `AI_SERVER_URL`, **`AI_SERVER_INTERNAL_KEY`** (`application-local.yml` 의 `ai-server.internal-key`)

**공개 엔드포인트:** devpick-ai는 `GET /health` 만 인증 없이 응답한다. 나머지 AI 기능은 **`/internal/*`** 에 모여 있으며 **`X-Internal-Key`** 가 필요하다.

| 용도 | devpick-ai 경로 | Spring 클라이언트 | 비고 |
|------|-----------------|-------------------|------|
| 질문 개선 | `POST /internal/refine` | `AiQuestionClient` | 요청: `title`, `content`. 응답: `refined_title`, `refined_content`, `suggested_tags` → Spring API는 `suggestions`로 매핑 |
| AI 1차 답변 | `POST /internal/answer` | `AiAnswerClient` | |
| 유사 질문 | `POST /internal/similar-questions` | `SimilarQuestionClient` | 응답 항목에 `text`, `tags` 포함 (Spring은 `question_id` 위주 사용) |
| 4레벨 요약 일괄 | `POST /internal/summaries` | — (백엔드에서 아직 호출 안 함) | 콘텐츠 본문 `text` + `content_id` — **레벨별 온디맨드 요약과 스키마가 다름** |
| 주간 리포트 인사이트 | `POST /internal/report` | — (배치/서비스 연동 시) | |
| 내부 헬스 | `GET /internal/health` | — | `X-Internal-Key` 필요 |

### 2-1. 레거시 문서의 `/api/summary`, `/api/quiz`, `/api/refine`

과거 초안에서는 Spring이 `POST /api/summary`, `POST /api/quiz` 등을 호출하도록 적혀 있었으나, **현재 devpick-ai 코드에는 해당 경로가 없다.**

| Spring 기존 기대 경로 | 현재 devpick-ai | 상태 |
|----------------------|-----------------|------|
| `POST /api/summary` (레벨 1개, `content_id`+`level`) | 없음 | `AiServerClient`가 호출 — **AI 측 구현 또는 Spring 쪽 호출 변경 필요** (예: 본문 전달 방식 협의, 또는 Mongo 캐시만 사용) |
| `POST /api/quiz` | 없음 (퀴즈 코드 없음) | 동일 |
| `POST /api/refine` | `POST /internal/refine` 로 통합 | **Spring은 `AiQuestionClient`에서 `/internal/refine` + 키로 연동** |

요약·퀴즈 온디맨드 계약은 팀에서 별도 확정 후, devpick-ai에 엔드포인트를 추가하거나 Spring `AiServerClient`를 새 스키마에 맞출 것.

## 3. 로컬 개발 시 포트 · 환경변수

| 서버 | 로컬 포트 | Docker 서비스명 |
|------|-----------|----------------|
| Spring | 8080 | `app` |
| FastAPI | 8000 | `ai-server` |
| PostgreSQL | 5432 | `postgres` |
| MongoDB | 27017 | `mongodb` |
| Redis | 6379 | `redis` |

| 변수 | 용도 |
|------|------|
| `AI_SERVER_URL` | Spring → FastAPI 베이스 URL |
| `AI_SERVER_INTERNAL_KEY` | Spring이 `X-Internal-Key`로 보내는 값 — **devpick-ai `INTERNAL_API_KEY` 와 동일** |

## 4. 팀별 요약

| 팀 | 구현 책임 |
|---|---|
| **Spring (백엔드)** | `POST /internal/contents` 수신 및 PostgreSQL 저장, FastAPI 호출 Client (`AiServerClient`, `AiQuestionClient`, `AiAnswerClient`, `SimilarQuestionClient` 등) |
| **FastAPI (devpick-ai)** | 수집 후 Spring으로 ingest, `INTERNAL_API_KEY` 보호 하의 `/internal/*` AI API, MongoDB·RAG·임베딩 |
